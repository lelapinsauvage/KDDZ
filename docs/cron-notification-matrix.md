# Cron And Notification Restoration Matrix

Legacy cron and notification behavior has two separate surfaces:

- Scheduled generators that create in-app alarm rows and delivery/read rows.
- Mobile push delivery through OneSignal player IDs stored in `notifications_tokens`.

Historical rows from `t_alarms*`, `custom_notifications*`, `notifications_tokens`, `t_notifications_log`, and `notifications_nature` are migrated by `src/scripts/migration/migrate-alarms.ts`. The remaining restoration work is future job generation and external delivery.

## Cutover Gates

1. Recover production crontab entries, timezone, URL parameters, and `gid` coverage.
2. Recover or retire the missing `../cronjob/functions.php` and `../cronjob/messages.php` helpers referenced by `cronjob.php`.
3. Confirm which commented daily cron blocks were actually enabled in production.
4. Implement idempotent modern generator jobs for each approved family with explicit dedupe keys.
5. Add provider-backed push/email/SMS/WhatsApp delivery only after credential recovery or rotation.
6. Record send attempts, provider response IDs, recipient IDs, read state, and failure reasons.
7. Run migration count reconciliation plus notification-family smoke tests before production cutover.

# Parent API Contract Matrix

Legacy native apps must keep working behaviorally through the modern parent API/portal.

The source-level navigation and modernization comparison is recorded in `docs/redesign/native-parent-navigation-comparison.md`; its executable 24-destination contract distinguishes working, hidden, placeholder, background, and external native capabilities without changing the parser contracts below.

Parent web PWA status:

- `/parent/login` now uses `/api/parent/login`, persists the parent JWT and child id in browser storage, and keeps failed login responses in the legacy `status: false` shape.
- `/parent` now consumes the daily detailed, finance, absence, grouped messages, message thread detail/reply, notifications, alarm feeds, push-token, food calendar, holiday calendar, and send-message endpoints as the first parent-facing web shell.
- Direct `/ws/*.php` routes and directory-prefixed `/:legacyPath/ws/*.php` aliases now exist for the active legacy native endpoints and delegate into the restored `/api/parent/*` contracts, so iOS/Android builds that still call literal PHP paths no longer require URL rewrites.
- Native parser field coverage is now codified in `src/scripts/verify-parent-native-parser-fields.ts` across the active iOS/Android parent feeds, including the iOS string-id login contract, and credentialed route-handler E2E is codified in `src/scripts/verify-parent-credentialed-native-e2e.ts` for login, daily/newdaily, absence, finance, food/holiday calendars, notifications, messagesList, message thread open/read reset, send/reply cleanup, push-token register/show/delete cleanup, and birthday/medicine/insurance/vaccination/payment/missing-report/assessment/event/general alarm feed headers and item fields. The latest non-sensitive run evidence is tracked in `docs/native-acceptance-ledger.md`; remaining contract work is external push/alarm delivery plus native-device acceptance.
